# format_broken

**답변의 구조가 깨졌는가.** 마크다운 뷰어에 넣었을 때 의도와 다르게 그려지거나,
텍스트 자체가 상한 경우를 켠다.

```
__init__.py      입구. 세 검사를 순서대로 부른다
markdown.py      L1 블록 구조 + L2 인라인 강조   ← 코드블록 밖만 본다
corruption.py    L4 문자 손상                    ← 답변 전체를 본다
```

층위 번호(L1·L2·L4)는 이 판정을 설계할 때 사고 유형을 갈랐던 이름이다. L3 이 비어
있는 것은 실수가 아니라 **일부러 뺀 자리**다 — 아래 "안 보는 것" 참고.

---

## 판정 순서

```python
if text.count("```") % 2:      return True    # ① 펜스 짝
if corruption.hit(text):       return True    # ② 문자 손상 — 전체 대상
return markdown.hit(prose_of(text))           # ③ 마크다운 — 코드블록 밖만
```

**①이 먼저인 것이 요점이다.** 펜스 짝이 안 맞으면 어디까지가 코드인지 정할 수 없다.
그 상태에서 `prose_of()` 로 갈라내면 경계가 틀리고, 틀린 경계 위에서 나온 ③의 결과는
믿을 수 없다. 그래서 갈라내기 전에 결론을 낸다.

**③이 `prose_of()` 를 거치는 것도 요점이다.** 코드 안의 파이프는 셸 파이프고 괄호는
정규식 문법이다 — 마크다운 구조가 아닌데 글자만 보면 구별이 안 된다. `prose_of()` 는
`_shared.py` 에 있고 `placeholder_leak` 도 같은 것을 쓴다.

## 무엇을 보나

### L1 블록 구조 (`markdown.py`)

| 검사 | 켜지는 예 |
|---|---|
| 펜스 ` ``` ` 홀수 | ` ```python ` 뒤에 닫는 펜스가 없다 |
| 표의 구분줄 없음 | `\| 항목 \| 값 \|` 다음 줄이 바로 데이터다 |
| 표의 열 수 불일치 | 헤더 3칸인데 구분줄이 2칸이다 |
| 헤딩 뒤 공백 없음 | `#환불 절차` — 제목이 안 된다 |
| 헤딩 7단계 이상 | `####### ` — 마크다운은 6단계까지다 |

표는 **연속된 블록 단위**로 센다. 이전 판은 `|` 가 든 모든 줄을 한 표로 셌고, 그래서
표를 두 개 쓴 답변은 열 수가 달라 무조건 깨진 것이 됐다. 표를 잘 쓴 답변일수록
걸렸다. 셀 안의 `\|` 는 칸을 가르지 않으므로 세기 전에 지운다.

### L2 인라인 강조 (`markdown.py`)

| 검사 | 켜지는 예 |
|---|---|
| `**` · `` ` `` · `~~` 홀수 | `**중요: 환불은 7일 이내입니다.` — 별표가 글자로 노출된다 |
| 링크 문법이 안 닫힘 | `[환불 정책](https://ex.com/refund 에 있습니다` |

여는 기호와 닫는 기호가 같아서 개수가 홀수면 짝이 없다는 뜻이다.

### L4 문자 손상 (`corruption.py`)

| 검사 | 켜지는 예 |
|---|---|
| 리터럴 `\n` 누출 | `1. 첫째\n2. 둘째` 가 통째로 한 줄로 찍힌다 |
| 대체문자 U+FFFD | 인코딩이 어긋나 남은 자리 |
| C0 제어문자 | 탭·개행·복귀를 뺀 나머지가 본문에 있다 |

이쪽은 `prose_of()` 를 통과시키지 않는다. 코드블록 안에서 상해도 상한 것이다.

리터럴 `\n` 누출은 **실제 개행이 하나도 없을 것**을 조건으로 단다. 개행이 있는데
`\n` 도 있으면 정규식이나 코드를 설명하는 정상 답변일 가능성이 높다.

## 일부러 안 보는 것

**여기가 이 문서에서 제일 중요한 부분이다.** 뺀 것에는 전부 이유가 있고, 이유를
모르면 다음 사람이 "왜 이건 안 잡지?" 하며 도로 넣는다.

| 안 보는 것 | 왜 |
|---|---|
| **`(` `)` `{` `}` 괄호 짝** | 오탐의 최대 원인이었다. `1) 첫째` 번호목록, `:)` 스마일, `(주)한국물산`, JSON 이 전부 켜졌다. 자연어에서 짝 없는 괄호는 깨진 것이 아니라 정상이다 |
| `*` 단독 짝 | 목록 마커 `* 항목` 과 곱하기에서 구별이 안 된다 |
| 리스트 번호 튐 (1, 2, 5) | 의도적으로 번호를 건너뛰는 답변이 흔하고, **렌더링은 실제로 안 깨진다** |
| 같은 줄·구절 반복 | 임계값이 순수 가정이다. 표·목록에서 반복은 정상이라 실제 답변을 보기 전에 정하면 그 숫자를 믿을 수 없다 |
| **L3 — JSON·HTML·LaTeX** | "답변이 그 포맷이어야 한다"는 전제가 있어야 성립하는데, 지금 그 전제를 확인할 수 없다. `schema.py` 의 컬럼 이름조차 실제 로그로 확인한 것이 아니다 |
| **플레이스홀더 누출** | `placeholder_leak` 의 몫이다. 포맷이 깨진 것이 아니라 답변이 미완성인 것이라 원인도 고칠 곳도 다르다 |

대괄호 `[` `]` 는 **센다.** 산문에서 대괄호는 거의 링크·각주 문법이라 짝이 맞는 것이
정상이고, `- [ ]` 체크박스도 `[1]` 각주도 짝이 맞는다.

### L3 구멍에 관한 경고

지금 `{"days": 7, "fee": 0,}` 같은 깨진 JSON 을 넣으면 화면에 뭔가 켜지긴 한다.
**그건 커버가 아니라 다른 판정의 오탐이다.**

```
깨짐  {"days": 7, "fee": 0,}  → language_mismatch
멀쩡  {"days": 7, "fee": 0}   → language_mismatch      ← 똑같다
```

`language_mismatch` 가 켜진 이유는 JSON 이 깨져서가 아니라 `days`·`fee` 때문에 답변의
지배 문자가 로마자로 잡혀서다. **깨졌든 멀쩡하든 똑같이 켜진다.** 이 숫자를 L3 의
탐지로 읽으면 안 된다.

## 이웃 태그와의 경계

숫자가 뜻을 가지려면 한 사고를 한 판정만 켜야 한다.

| 이웃 | 경계 |
|---|---|
| `answer_truncated` | 저쪽은 답변이 **중간에 끊긴** 것. 코드블록 짝은 이쪽이 본다 — 저쪽 `_hit()` 에 ` ``` ` 이 있으면 빠지도록 박혀 있다 |
| `model_thinking_stopped` | **빈 답변은 이쪽이 안 켠다.** 답변을 아예 못 받은 것은 저쪽 몫이고, 둘 다 켜지면 어느 쪽인지 알 수 없다. 저쪽이 `<think>` 짝도 보므로 여기서 HTML 태그를 보기 시작하면 겹친다 |
| `invalid_link` | 저쪽은 주소가 **성립하는지**를 본다. 이쪽은 링크 **문법**이 성립하는지만 본다 — 저쪽 정규식은 `[글](주소)` 가 온전할 때만 매칭되므로 문법이 깨진 링크는 그쪽 그물을 통과한다 |
| `placeholder_leak` | 채워지지 않은 빈칸은 저쪽 |

## 고칠 때

규칙을 넓히거나 좁히기 전에 **`tests/test_features.py` 의 표에 케이스를 먼저 더한다.**
그 표에 있는 것은 전부 한 번은 실제로 틀렸던 것들이다.

```bash
python -m pytest tests/test_features.py -q
```

`--dry-run` 두 모드는 유형당 한 개씩만 보장한다. 규칙이 살아있는지는 보지만
**정상 답변까지 켜는지는 보지 못한다.** 오탐은 저 표에서만 지킬 수 있다.

### 처음 재봤을 때의 숫자

현실적인 20 케이스로 잰 결과다. 이 판정이 왜 다시 쓰였는지에 대한 근거다.

```
이전   오탐 5 / 미탐 8
지금   오탐 0 / 미탐 2      ← 남은 둘은 위 "안 보는 것" 의 L3 과 플레이스홀더
```

느슨한 규칙이 만든 큰 숫자는 결과처럼 보이고, 콘솔이 유일한 출력인 이상 사람은 그
숫자를 그대로 옮겨 적는다. `sensitive_info` 는 1,000 행 중 980 행이 켜진 적이 있다.
**놓치는 것보다 거짓으로 켜지는 것이 나쁘다.**
